# 三维目标点控制（XYZ + yaw）

本入口在 Pelvis-1 策略上生成有界的骨盆参考，复用现有 Transformer 权重。
它不是训练新模型，也不是视觉导航、避障或自动搬运。
Z 是环境局部坐标中的**骨盆高度**，可表达身体升降目标；不是脚底地形高度或飞行指令。
代码与纯 CPU 回归已接入，真实策略验收必须单独记录，不能仅凭测试数量宣称行走能力达标。

2026-09-08 实测：仅降高分项在现有 3 cm 高度容限内通过（最终残差 2.68 cm）；
前进与组合目标仍停滞，**不能称为已验收的目标点行走或精确高度控制**。
见 [真实 actor 输入诊断及分项结果](ONLINE_WAYPOINT_DIAGNOSTICS_20260908.md)。

## 使用

在已有桌面终端，从仓库根目录启动：

```bash
BFM_LOAD_RUN=humanoid_transformer_m \
BFM_CHECKPOINT=model_22200.pt \
BFM_INITIAL_MOTION=ACCAD/Male2General_c3d/A1-_Stand_stageii \
BFM_MODE_INDEX=0 \
bash scripts/open_motion_browser.sh --online-targets
```

1. 等到 `READY`，确认模式为 `Pelvis-1`，点击 `Enable`。
2. 在 `Waypoint` 区填写**绝对环境局部 XYZ（米）**和 yaw（度），点击 `Go`。
   输入框初值来自真实骨盆位置，并非相对位移；例如要降高 6 cm，应把当前 Z 减 0.06。
3. 观察 `waypoint_state` 和详情中的目标距离、高度差、速度及停稳累计时间。
   `RUNNING` 表示执行中；`SETTLING` 表示姿态进入范围、仍需连续满足速度条件。
4. `Stop` 与 `Pause` 都立即暂停并取消运行中的任务。`Resume` 仍须新的有效 `Apply`；
   之后才可再次点击 `Go`。旧任务不会自动接着跑，Go 也不能绕过这道恢复门。
5. 手动提交一个有效 `Apply` 会取消当前任务并接管参考。切换控制模式也会暂停/取消任务。
   `UMI-2` / `VR-3` 中 Go 禁用，不能自动切换成 Pelvis-1 或偷偷启用物理。

关闭用 `Exit` / 面板 X；紧急停止本启动器的进程组：

```bash
systemctl --user stop bfm-motion-browser.service
```

不使用面向所有 Python 或 Isaac 进程的 `pkill`。

## 有界参考与真实到达

| 项目 | 默认规则 |
| --- | --- |
| 单次三维距离 | 距真实起点 ≤0.5 m |
| 单次高度变化 | 相对真实起点 ≤0.15 m，且必须通过既有 Provider 的初始高度工作空间 |
| 朝向变化 | 最短角距离 ≤45° |
| 参考三维总速度 / 竖直速度 | ≤0.08 / 0.04 m/s |
| 参考相对真实位置的前探距离 | 0.10 m；实际位置退后时停止参考推进，不瞬移参考去追机器人 |
| 参考 yaw 速度 | ≤0.25 rad/s |
| 到达位置 / 高度 | 三维距离 ≤0.05 m，且绝对高度误差 ≤0.03 m |
| 到达朝向 | yaw 差 ≤5° |
| 停稳速度 | 三维线速度 ≤0.05 m/s，角速度模长 ≤0.10 rad/s |
| 连续停稳 | 上述条件同时满足 ≥0.5 秒**实际仿真步时间** |
| 超时 / 停滞 | 15 秒任务时间；距目标未能再缩短 0.01 m 持续 4 秒视为停滞，位置容差内的等待不消耗停滞预算 |

这些是当前保守的工程约束和任务判据，不是所有这些范围均已可靠实现的保证。
`ARRIVED` 仅在真实状态满足判据后产生；参考走到终点但身体没到，不能算成功。
ARRIVED 后参考保持，**策略和物理继续运行**，不通过冻结仿真宣称停止。
任务结果和终端遥测是该任务结束时的快照；后续长期保持和扰动恢复仍需独立评估。
`TIMED_OUT` / `STALLED` 会暂停，不能当作成功；非有限遥测/失联沿用在线会话的故障门控。

## 技术说明

`Waypoint GUI → 三维参考规划器 → Provider → 原 Transformer → 29 维关节动作 → 真实 PhysX`

规划器没有环境对象，只消费真实 XYZ、yaw 和速度。只有 `after_step` 通知推进任务时钟；
UI 更新或暂停期间不累计到达时间。按本机 IsaacLab API，从 body-link 的世界系速度读取
完整三维向量，并解开 ProxyArray 的 `.torch`；不把关节速度或参考速度当作骨盆速度。

新任务先校验最终 XYZ/yaw 与 Provider 工作空间，再原子替换待执行参考。
单位四元数、时钟和序号校验仍保留。骨盆参考的平移同时传到完整包中未激活的腕参考，
仅为了保持 Provider 的相对工作空间约束；腕不进入 Pelvis-1 的 actor 约束，**这不是双腕搬运**。

内部参考提交在下一次 `before_step` 消费 UI 意图之后发生，序号与 UI 共用递增源，
避免在 `env.step` 期间排队的手动 Apply 被内部参考序号越过。提交只刷新 task/mode 观测，
`update_history=False` 不推进身体/动作历史。没有机器人 reset 或 root/joint state-write。

规划器的 `preview` 在临时副本上生成未来 XYZ/yaw，不修改任务状态或计时。
Provider 接收 34 帧显式轨迹：第 0 帧必须匹配当前参考，第 1–33 帧间隔为控制步长
（本机 0.02 秒）；公开采样为 offset 0–32，额外第 33 帧用于最后一帧速度差分。
每一帧都通过原工作空间与速率校验，排队后 commit 再核对第 0 帧，避免过期轨迹造成跳变。
只有实际 command step 消费下一帧；重复 sample/GUI 刷新不前移轨迹。

这样 actor 的 `[0, 1, 2, 3, 4, -1]` 未来窗口能看到连续参考，而非只有下一小步、
其余帧全是停止姿态。预览期间把当前真实位置固定，仍受 0.10 m 前探边界约束，
每个真实控制步重新规划；机器人跟不上时不会不断把参考推远。普通 Apply、参考重播种、
关闭会清理显式轨迹。参考机制正确不等于已有权重一定能够执行该目标，必须实测。

原在线暂停、心跳、模式版本和退出规则见 [在线控制说明](ONLINE_VR3_CONTROL.md)。
