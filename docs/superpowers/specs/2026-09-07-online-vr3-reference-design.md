# GUI 在线骨盆与双腕控制设计

日期：2026-09-07。

状态：用户已要求按本设计开始开发；实现与验收进度见配套实施计划。
本文出现的新模块名、开关和验收项都是实现契约，不是已经可运行的功能或测试结果。

## 1. 目标与边界

在现有 ScaleTrack IsaacLab 播放器中，增加可选的本地在线参考输入：用户在原生
Kit GUI 中修改骨盆、左腕和右腕的目标位姿，由现有 Transformer 策略输出关节动作，
让机器人通过物理仿真响应。连续修改目标不重置机器人、不直接写入机器人状态。

首版限定单个 G1 29 DoF、平地、VR-3 掩码、固定世界轴方向的环境局部坐标。
沿用现有 IsaacLab 和权重格式，不重装依赖，不改变 PPO、网络结构或训练数据。
GUI 默认 checkpoint 不因本功能而更换；新增 KIT 训练副本不自动升级为默认策略。

不包含网络动捕、ROS、设备遥操作、真机控制、避障导航、自动抓取、夹箱搬运、
接触实物标定或新一轮长训练。场景中的箱子可以保留，但本功能不控制其状态。
KIT 的数据接入与单次训练更新已另有记录，不是在线控制成功的证据。

本里程碑区分三件事：参考接口正确、实际跟踪表现、物体任务成功。
本设计验收第一项，并测量第二项；不把第一项通过写成后两项已经实现。

## 2. 决策及依据

采用显式、可选的 `LiveReferenceProvider`，加上 `MotionCommand` 的薄适配层。
provider 不依赖 Kit GUI、场景或机器人写接口；GUI 只提交完整目标意图。
现有离线参考在未启用在线模式时走原路径。

不选临时替换播放对象方法作为正式架构：当前值、未来值、速度、时间、缓存和
自动复位容易出现不同步。不在首版搬入完整 ScaleBridge：网络分包、并发缓冲和
设备生命周期不是这次本地 GUI 闭环的必要条件。也暂不复制完整独立环境任务，
以避免出现两套训练与播放配置。

本地源码已核对的约束：

- `playback_menu.switch_motion` / `switch_mode` 会触发复位，不能用作目标更新。
- `MotionCommand._resample_command` 会写机器人根状态和关节状态。
- IsaacLab `ManagerBasedRLEnv.step` 在命令更新前计算终止并执行自动复位。
- 当前 `motion_time_out` 没有 `disable_flag`，只调用现有评估设置不足以阻止片段结束复位。
- `--local_tracking` 会将机器人根位置观测替换成参考根位置；在线首版禁止与它组合。
- 策略和 critic 使用不同未来采样索引；不能只为 GUI 或 actor 生成一个当前目标。

## 3. 组件与数据流

```text
Kit 面板：三个目标位姿、启用、暂停、恢复、退出
    ↓ 完整不可变目标包；回调不访问仿真写接口
单槽待处理队列：原子提交、覆盖尚未消费的旧有效包
    ↓ 仿真循环边界校验与消费
在线监督器：状态、输入新鲜度、机器人异常、退出
    ↓ 仅 ACTIVE 状态推进参考与策略
LiveReferenceProvider：连续限速参考 + 未来参考采样
    ↓ MotionCommand 参考读取适配；清除参考缓存
现有观测与 VR-3 掩码 → 现有 Transformer → 关节动作 → 物理仿真
    ↑ 直接读取真实 Articulation 状态用于观测、监督与误差报告
```

拟新增纯逻辑模块 `scaletrack/utils/live_reference.py`，负责目标数据、校验、
时钟与插值；播放侧 `online_control.py` 负责监督和接线，`online_ui.py` 负责 Kit
控件。`commands.py` 只增加可选参考源接入口，不把 UI 或网络放进 MDP 命令。
这些文件名用于明确职责，内部类的拆分可以在实现计划中细化。

provider 附着后不再读取持续推进的离线片段作为在线参考。
离线数据仍可用于原有初始化，但不能通过改写 `cat_*` 数组伪造实时动作文件。
在线时间独立于 `motion_ids`、`time_steps` 和原片段长度。

## 4. 目标坐标与完整性契约

### 4.1 身体点与单位

身体顺序沿用配置中的 14 个参考连杆；三个激活点必须按名称解析，再断言对应关系：

| GUI 目标 | 连杆名 | 当前参考数组索引 |
| --- | --- | ---: |
| 骨盆 | `pelvis` | 0 |
| 左腕 | `left_wrist_yaw_link` | 10 |
| 右腕 | `right_wrist_yaw_link` | 13 |

GUI 位置单位为米；坐标为右手系、Z 向上，与场景世界轴同向的环境原点平移坐标，
不是随机器人转动的身体坐标。X/Y 不按当前机器人朝向重新定义。
转成世界位置时仅加一次 `scene.env_origins`。必须以非零环境原点做测试。
GUI 姿态输入为 XYZ 欧拉角、显示单位度，明确使用与本地 `quat_from_euler_xyz`
相同的约定；输入边界转换成归一化 `wxyz` 四元数。
适配 IsaacLab 时使用已有 `quaternion_compat` 的运行时顺序检测与转换，
不能根据目录名假设运行时使用 `wxyz` 或 `xyzw`。

### 4.2 原子目标包

每次提交包含递增序号、单调时钟时间、坐标与四元数约定、三个连杆的完整位置和姿态。
UI 编辑一个字段时，提交的是编辑后的完整三目标快照，不让消费者读到半包。
输入数组复制并保持快照不可变；同一渲染周期内的连续有效编辑允许合并为最新包。

入口及消费边界都校验：完整且唯一的连杆集合、精确形状、有限数值、正确约定、
递增序号以及工作空间限制。拒绝缺点、重复点、NaN、Inf、旧序号、非法时间和零四元数。
四元数范数偏差不超过 `1e-3` 时归一化；更大的偏差拒绝。
`q` 与 `-q` 表示同一姿态，插值必须走最短弧，不能产生整圈旋转。

首版默认工作空间是工程输入限制，不代表已证明可达或安全：骨盆水平距启动种子位置
不超过 1 m，高度位于种子高度 ±0.15 m 与 `[0.35, 1.25]` m 的交集；每只腕到
同包骨盆的距离不超过 1 m。种子本身不符合限制时拒绝启用并解释原因，不修改真实姿态。
所有限制进入启动配置与报告，不能静默放宽。

非法包整包拒绝，保留上一个有效目标及待消费有效包；GUI 显示原因与拒绝计数。
非法编辑本身不触发机器人重置，也不覆盖上次接受序号。

## 5. 时间与参考生成契约

### 5.1 连续参考

在初始化完成、尚未推进在线物理步时，从真实机器人读取 14 连杆位姿和 29 关节位置，
形成种子快照。初始化与在线激活分开记录；激活本身不写任何机器人或物体状态。
在线首版不从三个目标求解完整 IK。非激活连杆位姿和关节参考固定为种子值，
其参考速度为零；只将三个激活连杆的位姿替换为在线轨迹。
这些非激活值只保持接口完整，不代表物理可实现的全身姿态。

每个物理控制步从上一参考位姿朝最新有效目标做限速平移与最短弧姿态插值。
默认平移速度上限：骨盆 0.2 m/s、双腕各 0.35 m/s；角速度上限：骨盆 0.5 rad/s、
双腕各 1 rad/s。新目标到达不能使当前参考位置或姿态跳变。
这是连续位姿和速度限幅，不承诺加速度或 jerk 连续，也不是实物标定参数。

未来参考按当前参考状态、同一锁存目标和同一限速规则预测。
位置、姿态、线速度和角速度来自同一轨迹；速度按相邻参考帧差分计算，旋转差分使用
最短弧并明确为世界轴方向角速度。到达后恒定目标的速度为零。
最后一个对外帧的速度通过额外一帧内部预测求得，不以任意零值拼接。

### 5.2 观测兼容

当前控制步长由环境读取，现有配置为 `0.005 × 4 = 0.02` s。
对外支持当前帧及未来 32 帧，覆盖 `0..32`，在该步长下为 0.64 s；
生成轨迹使用秒，传给网络的原有 timestamp 特征仍是帧偏移，不改成秒。

| 现有消费者 | 保持的采样契约 |
| --- | --- |
| actor task | `[0, 1, 2, 3, 4, -1]`，6 个时间点 |
| critic task | `[0, 1, 2, 4, 8, 16, 32]`，7 个时间点 |
| 通用 future 属性 | 33 个连续帧加原有随机时间点，保持原返回长度 |
| `-1` | 复用该环境既有随机帧偏移，当前范围为 5 到 32，不在每次读取时重抽 |

当前、manual future、通用 future、anchor、关节参考及相应速度必须一致，
不能有部分 getter 继续读不断推进的旧片段。未知或超出支持范围的索引明确报错。
参考缓存以参考版本和控制帧为边界失效，同帧不同消费者看到同一快照。

目标消费发生在下一次策略推理之前。接受新目标后，在该步消费的观测中体现其未来
轨迹；不沿用上次 `env.step` 留下的旧 task 观测。刷新 task 观测不追加真实状态历史，
使用本机已核对的 `compute_group(..., update_history=False)` 语义。
一次物理步只追加一次 proprioception/action 历史，不新增观测噪声采样。

VR-3 模式使用现有显式掩码推理路径，不能落入默认 inference 的全点条件路径。
网络键名、特征布局、14 连杆顺序、29 动作维及 checkpoint 严格加载保持不变。
奖励和旧 14 连杆/关节参考指标在该模式下不代表在线稀疏控制成功；另报三个激活点误差。

## 6. 暂停、失效与无自动复位

状态包括 INITIALIZING、READY、ACTIVE、PAUSED_USER、PAUSED_FAULT 和 CLOSED。
初始化完成进入 READY，先暂停物理，由用户显式启用；初始化过程产生的正常复位
单独记录，不计为在线目标更新。ACTIVE 才执行策略与物理控制步。

本地 GUI 的目标是锁存设定值，不要求用户持续拖动滑块。
生产端运行正常时，即使目标不变也保持心跳；消费者用独立的单调时钟检查心跳。
默认超过 0.5 s 未收到生产端心跳，或收到时间倒退/未来时间的损坏包，进入
PAUSED_FAULT。单纯目标值保持不变不算超时。默认阈值写入日志，不宣称实时性保证。
此心跳只能检测消费者仍在执行时的生产端失效；整个进程/主线程卡死不在其检测能力内，
有界验收另设外部进程组超时。

动作与观测非有限、真实机器人状态非有限时禁止下一物理步。
每次物理步前后检查真实骨盆高度与姿态：高度低于 0.35 m，或骨盆局部竖直轴与
世界竖直轴点积低于 0.5，记为首版跌倒保护触发并暂停。
这些是保守工程阈值，不是一般动作跌倒分类器；不能将正常深蹲等任务据此判为模型失败。
三个目标跟踪误差持续记录，但不直接当作跌倒。

暂停必须停止物理推进并继续处理 GUI 事件，不能通过零动作、反复 `env.step` 或
写入冻结状态来伪装暂停。利用本地 `SimulationContext.pause/play` 与非物理界面更新，
实测暂停期间仿真时间、关节和物体状态不推进。恢复需用户确认、生产端新鲜、真实状态
有限且未触发跌倒保护；不会自动起身或重置。跌倒后需退出本次在线会话，重新初始化。
恢复时抛弃暂停前待处理包，以当前真实姿态重新建立参考起点，并要求用户重新提交目标；
这不重置机器人、episode、动作或观测历史，也不移动启动时确定的工作空间边界。
Kit 原生暂停操作映射为 PAUSED_USER；原生播放按钮不得越过故障锁存直接推进物理。

在线配置在 `gym.make` 前移除本任务的 time_out、motion_time_out 和 body_pos
自动终止项，替换为上述外部监督；只修改本次播放配置实例，训练和离线默认不变。
启动时断言自动终止项和会写状态的周期事件未启用。关闭命令定时重采样，
并在 provider 已附着时拒绝会写状态的 `_resample_command` 路径。
不能仅延长片段或 episode 长度来规避复位。

在线开始后不调用 `env.reset`、`switch_motion`、`switch_mode` 或机器人状态写接口。
UI 动作/掩码切换、物体复位按钮禁用；首版需要退出并按原命令重新启动才能返回离线播放。
物体始终只接受真实物理作用，不绑定、吸附或写参考轨迹。

## 7. GUI、启动与资源所有权

拟新增显式 `--online_targets` 选项；首版仅接受 `G1-BFM-Transformer-Tracking`
任务，要求 `--motion_menu`、Kit GUI、
`--num_envs 1`，固定 VR-3。冲突的模式参数、`--local_tracking`、多环境、
headless 或 video 组合在仿真启动前拒绝。自动化无头测试使用独立测试入口，
不把它暴露成未经验收的用户运行模式。
现有启动器可增加一个明确的在线选项，但默认启动命令与权重保持原样。

界面显示三个位置/朝向编辑组、目标/实际位置、目标标记、三个激活点位置/姿态误差、
状态、暂停原因、最后接受序号、输入年龄及拒绝次数。显示目标轨迹与实际运动的区别；
不把目标标记当作机器人真实位移。数值编辑和暂停/恢复可用，不要求新建网页 GUI。

沿用 `ExitStack` 和现有主程序 `finally` 管理生命周期：停止接受新意图，释放
UI 订阅及窗口，再关闭环境和 SimulationApp。初始化失败、Ctrl-C、窗口关闭、
待消费包尚未处理及运行异常都走同一清理路径，异常保留非零退出码。
首版不创建 socket、后台线程、常驻服务或另一个 GUI 进程。
测试进程有明确上限与精确所属进程组；不使用广域 `pkill`，不停止用户无关任务。

## 8. 验收与证据

### 8.1 纯逻辑与契约测试

- 目标集合、形状、单位、四元数双约定、符号等价、非零环境原点和工作空间边界。
- 原子快照与最新有效包合并；输入被外部修改不影响已提交包；坏包不破坏上次有效状态。
- 至少连续 100 次有效目标更新，参考连续、速度不超过配置，且目标确实进入下一次观测。
- actor 6 帧、critic 7 帧、通用 future、当前/anchor/速度/时间的一致性；
  读 getter 不推进时间、不重抽随机帧、不改变观测历史。
  同权重的离线基准与在线观测逐键比较 shape、dtype、device 和特征布局。
- 无编辑但心跳正常不超时；模拟生产端停止、旧包、未来/倒退时间、非法动作和跌倒保护。
- 暂停状态不调用物理步；恢复必须显式且满足条件，关闭后不能再提交目标。

### 8.2 集成和回归

- 初始化之后监测 `env.reset`、`_reset_idx`、命令重采样及机器人/物体状态写接口；
  100 次在线更新的这些状态重置/写入计数必须为 0。单独消费目标包前后，
  episode 计数、历史缓存、上次动作和真实机器人状态不变。
  正常关节控制目标下发与仿真内部积分不算直接写状态。
- 使用短种子片段运行超过原片段长度及原 10 s episode 长度，确认无隐藏自动复位。
  必须在 mock 生命周期测试完成；真实运行若提前跌倒暂停，记录为未覆盖长运行条件，
  不能为了通过测试禁用监督或重复重置。
- 真实 checkpoint 严格加载，actor 输入/输出有限，激活点确为 VR-3；
  同权重同种子且在线开关关闭时，离线路径行为保持原有语义。
- 运行现有完整相关回归命令，205 项是上一轮基线数量，不是本次已通过结果：

### 8.3 真实 GUI 有界验收

单进程、单环境，单次最长 3 分钟墙钟时间；正常、暂停恢复、坏输入、关闭和初始化
失败分别留证。实际点击或 GUI 回调驱动三个目标的小幅变更，确认不是只更新控件。
刻意设置不同的真实/目标位姿，核对 GUI 两类数值分别来自真实 articulation 与参考源。
记录 checkpoint SHA、代码/配置指纹、种子参考、接受/拒绝包数、物理步数、参考与真实
轨迹、三个激活点的平均/最大位置和姿态误差、暂停事件及全部复位计数。

至少一次故障暂停持续 2 s 墙钟时间，验证仿真时间及真实状态不推进且 GUI 仍能关闭。
正常、暂停与故障状态下，退出请求均须在 15 s 内完成；初始化异常保持非零退出码。
结束核对所属进程组为空、环境已关闭，不残留本任务 GPU 进程或新增 IPC 资源。
视频不是首版必要验收项；未解决授权前不自动上传数据、权重或派生录像。

若策略在小幅目标下失稳，报告真实误差和触发原因，结论仅为接口是否正确；
不能用一段短暂正常画面替代跟踪质量验收，也不能宣布任意目标控制已学会。

## 9. 后续连接点

接口与 GUI 验收后，再单独设计在线目标点到达/停止评价，并根据实测决定是否进行
