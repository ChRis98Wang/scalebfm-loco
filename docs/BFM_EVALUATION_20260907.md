# 2026-09-07：官方与本地最终权重的配对评估

## 结论

**在本轮 WholeBody-14 验证协议下，本地最终权重弱于官方起点。**
平均世界坐标身体位置误差增加 **20.10%**，四个数据集分组的平均误差均增加。
962 条动作中，145 条均值改善、817 条变差；不能把本次微调称为整体提升。

这不表示训练没有更新参数，也不能直接证明所有稀疏控制模式都退步。
当前已证实的是：官方预训练 Transformer + 本地 PPO 微调能执行参考动作跟踪，
但最终权重没有通过本轮全身跟踪基线比较。尚未证实自主目标规划、物体交互任务
或完整 BFM 论文效果。

## 两组完全相同的评估条件

- 官方起点：`humanoid_transformer_m/model_22200.pt`。
- 本地最终：`amass_full_v1_finetune_20260906/model_23197.pt`。
- 任务 `G1-BFM-Transformer-Tracking`；固定 `WholeBody-14`，种子 42，128 环境。
- 验证集 962 条；本地训练索引 4,247 条，动作 ID 无交叉。未证明人员身份级别、
  语义级别或官方预训练数据级别的独立性。
- 50 Hz，每条统计 `min(N - 1, 1000)` 步；每组共 342,637 个有效步。
  81 条长动作截断至前 20 秒，剩余 881 条覆盖全部有效推进步。
- 无训练更新；均值策略；关闭观测噪声、重置扰动和周期推力，保留相同种子的
  默认启动随机化。地面为本地无限静态平面，原物理材质参数保留。
- 均值先在动作内计算，再对动作等权平均；不混入自动重置样本。
- 已校验两份 v2 报告的任务、模式、种子、环境数、步长、软件版本、动作 ID、
  每条步数、全部 NPZ 字节和实际 Python 源码一致；每组运行前后的输入校验均通过。

完整口径见 [评估入口和协议](BFM_EVALUATION.md)。不要与旧训练内评估数值直接做前后比较。

## 整体结果

误差越小越好；下面的“超阈值”不是物体任务失败率，也不是专门的跌倒检测。

| 指标 | 官方起点 | 本地最终 |
|---|---:|---:|
| 世界坐标身体位置均值误差 | 5.6548 cm | 6.7914 cm |
| 去根平移后的身体位置均值误差 | 2.7749 cm | 3.8446 cm |
| 根位置均值误差 | 4.8849 cm | 5.5947 cm |
| 超过 0.1 m 阈值的动作 | 389 / 962 | 532 / 962 |
| 超过 0.2 m 阈值的动作 | 41 / 962 | 91 / 962 |
| 超过 0.5 m 阈值的动作 | 2 / 962 | 7 / 962 |

阈值检查的是每个时刻 14 点平均世界坐标误差，在评估窗口内的最大值。
即便宽松的 0.5 m 标准通过率超过 99%，也不能掩盖误差增大，更不能说“99% 复现”。

## 下一环节：先把基线选对，再做稀疏任务控制

1. 保留官方起点作为目前已验证的全身跟踪对照，不删除本地权重，也不擅自替换 GUI 默认模型。
2. 对两套权重补充 Pelvis-1、VR-3 和多种子评估，区分全身跟踪退步与不同输入模式之间的取舍。
3. 查训练学习率、模式采样比例、数据分布及中间 checkpoint。过拟合或预训练能力遗忘只是
   待检验假设，当前对比本身不能确定原因。使用验证集调参后，最终泛化结论还需独立测试集。
4. 确认基线后，再实现明确的在线目标任务接口：先目标点行走/手腕目标跟踪，之后才讨论
   带物体的抓取和搬运；分别定义成功率、跟踪误差和稳定性标准。

本轮到此完成独立配对评估；上面的后续实验尚未运行。现有数据足以做这些检查，
CMU 不是进入下一步的前置条件。GUI 地面最终视觉验收仍待桌面解锁。
