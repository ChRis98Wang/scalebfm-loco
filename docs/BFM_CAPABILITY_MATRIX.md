研究展示、现成源文件和本机通过验收的能力混为一谈。

这是新的数据生产候选功能，不是八模式策略跟踪验收、PPO或物体交互能力；下一段才扩同源样本并验证策略。

## 官方范围与本地范围

ScaleBFM 的核心是参考目标条件下的全身运动控制，包含八种身体点约束模式。
官方同时提供重定向、PPO 预训练、策略导出以及 ScaleBridge 部署/遥操作入口。
项目也明确提到，与上层策略的结合仍有待研究；因此不能把一个 BFM checkpoint
当成自动具备视觉识别、路径规划和物体任务决策的完整机器人系统。
来源：[官方项目说明](https://scalebfm.github.io/)、
[ScaleTrack](https://github.com/zengweishuai/ScaleBFM/blob/main/ScaleTrack/README.md)、
[ScaleBridge](https://github.com/zengweishuai/ScaleBFM/blob/main/ScaleBridge/README.md)。

“代码已有”只说明文件存在；“运行通过”只说明指定输入下流程执行完成；
“能力验收”还需要预先定义的任务、成功标准、失败率和可复查结果。
源码功能覆盖、论文实验复现、实物表现是三个不同目标，不用单一百分比混合表示。

## 后续实现顺序及验收门槛

1. **BFM 控制层优先**：补齐八模式、global/local 的完整回归；新增在线参考源，保持
   29 维身体动作和已有 checkpoint 输入约定，旧动作播放和训练数据流不变。
   在线输入明确身体名、世界/局部坐标、wxyz 四元数、时间戳与目标有效期；拒绝
   非有限值、错误维度、乱序/过期目标。更新目标不靠反复重置机器人实现移动。
2. **可操作的在线控制**：骨盆位置/朝向与双腕目标、GUI/键盘目标入口、无设备回环测试。
   先验证有限速度的连续目标与停止，分别记录真实机器人误差、超时和失稳。
   有真实设备时再验收遥操作输入，不把合成输入称为硬件连接成功。
3. **部署链路**：导出一致性、MuJoCo 回放与坐标/关节顺序检查。当前 TensorRT 未就绪
   不通过升级现有 IsaacLab 强行解决；部署依赖和输出隔离，真机动作仍需单独授权。
4. **双臂搬运任务**：接近箱子 → 双臂夹持 → 抬起 → 搬运 → 放下。使用现有末端，
   不添加手指。除环境 reset 外不直接写物体轨迹，不焊接/绑定箱子到手上；保持、移动
   和放下依赖真实碰撞与摩擦。分别统计双侧接触、抬升保持、滑落、落区、跌倒及超时。
   首先训练/验证有明确范围的轻箱子任务，再扩展对象质量、尺寸和位置分布。
5. **标定与发布**：完成可记录数据来源的标定工具；实测数据缺失时保留未标定状态。
   补发布检查，不因仿真流程跑通就宣称真实材料一致或自动允许公开数据/权重。

这份表是当前审计与分阶段设计，不是已经完成上述待办的报告。
采用 `brainstorming` 的分层设计区分控制器、任务和实物验证；IsaacLab API 核对使
当前 29 DoF 资产与真实状态读取约定保持明确。KIT 数据检查不改变这个功能优先级，
不等待继续下载 CMU 才开展核心控制工作。
